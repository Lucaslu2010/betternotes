# October iPad release checks

The app target is iPad only. Debug and Release use local SwiftData stores. A paired iPad and Mac exchange editable notebooks over the local network while both apps are open. Editable `.betternotes` export and import remain available as recovery paths.

The editor keeps the frequently used drawing tools, undo/redo, and Insert within reach; the page-count control opens Page Overview, and less frequent page actions live in More. ## Nearby sync validation

On 24 Sep 2026, a signed iPad-to-Mac nearby transfer completed. The Mac library received the iPad notebooks and the status bar reported a completed sync. After reopening the Mac app, another automatic sync completed. A synced page containing black handwriting and red marks was inspected on the Mac; both colors are visible after the Mac ink-rendering fix.

A physical sync pass exposed repeated conflict copies. The cause was unstable snapshot hashes from sub-microsecond date drift and pages that shared an index but exported in different relationship orders. Both were fixed, with regression tests. After the updated builds reconnected, the Mac reported **0 new, 1 updated, 0 conflict copies**; copied live stores on both devices each contained **21 total notebooks, 6 active**. Earlier conflict copies remain in the libraries and Trash. They have not been deleted because their contents may differ. Recheck after further edits and reconnections before treating duplicate creation as fully validated.

Later, editing an answer card produced one more active copy of its two-page notebook. Its ink and OCR matched the source, but the assistant card state differed. The sync protocol did not acknowledge which outgoing notebook versions the other device had accepted, leaving a stale merge baseline after a successful transfer. The protocol now exchanges per-notebook acknowledgements in both directions and ignores acknowledgements for versions it did not send. Both stores were backed up before this change. With version 2 installed on both devices, automatic reconnect at 22:07 reported **0 new, 1 updated, 0 conflict copies**. Copied live stores each held **22 notebooks, 7 active**, and the completed answer card was present on both devices. A Mac relaunch reconnected at 22:11 with **0 new, 0 updated, 0 conflict copies** and still 22 notebooks. A fresh iPad edit and bidirectional edit check are still needed before declaring duplicate creation resolved.

On 29 Sep 2026, protocol version 4 was installed on the signed iPad and Mac. It resolves a true concurrent edit by preserving the first receiver's local version once, then adopting the sender's version under the original notebook ID. Both builds completed a physical nearby exchange. The first reconnect after several days and schema changes kept seven older, already trashed revisions as conflict copies; the resulting libraries each held 33 notebooks with matching stable IDs. A second reconnect reported **0 new, 0 updated, 0 conflict copies** on both devices. The Mac then moved four distinct legacy conflict versions from Notes to Archive; the iPad received those four updates with **0 conflict copies**. Both libraries now have **4 Notes, 4 archived, and 25 in Trash**. Read-only copies of both stores had matching content for all 33 IDs. A further Mac reconnect after the final iPad build reported **0 new, 0 updated, 0 conflict copies**. Recovery copies from before and after the first exchange are stored locally at `~/Library/Application Support/BetterNotesSyncBackups/2026-09-29`.
